## EXECUTIVE SUMMARY

### Release Objective
R2.2 establishes **workspace-level revenue visibility** by surfacing existing Invoice/Payment/Revenue data through a dedicated top-level navigation area, separating the AI Assistant from Reports, and enabling structured data export (Excel/PDF).

R2.2 does **NOT** redefine Invoice/Payment creation workflows.  
R2.2 does **NOT** reimplement Accrued/Expected/Forecast.  
R2.2 does **NOT** change existing Contract → Invoice → Payment semantics.

### What PO Confirmed
- Invoice creation UI **exists and is clear** (Contract → Invoices)
- Payment recording UI **exists and is clear** (Invoice → Payments)
- PO has created real invoices successfully
- Problem = **workspace-level discoverability/reporting**, not workflow redesign

### R2.2 Scope (All 5 Areas REQUIRED)
1. **Revenue Visibility** - workspace-level Accrued/Expected/Invoiced/Paid/Outstanding
2. **Workspace-level Invoice/Payment Access** - dedicated navigation, list/filter/search
3. **AI Assistant Separation** - remove AI from Reports; create dedicated Assistant surface
4. **Excel Export** - selected reporting datasets
5. **PDF Export** - selected reports/datasets

### What Exists Today (R2.0-R2.1 Implemented)
- **E01:** Accrued Revenue (TimeEntry snapshot), Expected Revenue (HOURLY capacity)
- **E02:** Invoice Tracking (Contract-scoped, operational, ACTIVE/VOID)
- **E03:** Payment events (Invoice-scoped, sum = paidAmount, amount status, overdue, alerts)
- **Reports:** `/reports` - ContractReport, HoursByClient, AnnualOverview, period filters, CSV export
- **AI:** AnalyticsAskBox on `/reports` only; orchestrator + tool registry; grounding; Claude Haiku 4.5

### What R2.2 Adds
- Dedicated **`/invoices`** or **`/revenue`** route (workspace-level)
- Invoice list with filters (ACTIVE/VOID, client, contract, date range, amount status, overdue)
- Revenue summary cards (Accrued, Expected, Invoiced, Paid, Outstanding) - strict currency separation
- AI Assistant moved to **`/assistant`** or similar; Reports gets an entry link
- Excel export for ContractReport + HoursByClient + optional Invoice list
- PDF export for selected reports (layout/formatting defined in planning)

### What R2.2 Does NOT Add
- New Invoice/Payment creation forms (already exist)
- Profitability/Cost/Margin (PIVA Balance owns this)
- FX or mixed-currency totals (D7 boundary)
- Workspace-base currency rollup (out of scope)
- Invoice lines, fiscal numbering, PDF generation (Invoice Lifecycle - out)
- New Accrued/Expected formulas (E01 is authoritative)
- New reporting datasets (reuse existing AnalyticsService)
- AI capabilities beyond current tool registry

## 1. CURRENT-STATE ARCHITECTURE

### 1.1 Domain Model (R2.0-R2.1)

**Entities:**
```
Workspace 1 → N Contract 1 → N Invoice 1 → N Payment
Client 1 → N Contract
TimeEntry → Contract (snapshot: billingModel, rate, currency)
```

**Revenue Types (E01):**
- **Accrued Revenue** = billable TimeEntry consumption × snapshot commercial value (HOURLY additive, DAILY one-day-per-date, R2-OD-001/016)
- **Expected Revenue** = HOURLY live Contract rate × pro-rata `monthlyContractedMinutes` (DAILY → null)
- **Forecast Revenue** = deterministic linear projection (E04, not in R2.1)

**Invoice/Payment (E02/E03):**
- **Invoice** = operational tracking record (date, amount, currency snapshot, optional reference, paymentTermsDays snapshot, dueDate)
- **Payment** = event against Invoice (date, amount, currency = Invoice currency)
- `paidAmount` = SUM(Payment.amount) where invoiceId
- **Amount Status** (derived): UNPAID (0), PARTIAL (0 < paid < amount), PAID (paid = amount), MISMATCH (paid > amount)
- **Overdue** (independent): `dueDate ≠ null AND dueDate < today AND paidAmount < amount`
- **Tracking State**: ACTIVE | VOID (one-way soft-delete)

**Invariants:**
- 1 Invoice → exactly 1 Contract
- Invoice currency = Contract currency (snapshot, immutable)
- Contract currency immutable after first Invoice/Payment
- Invoice VOID → Payment create/update/delete forbidden (E03-D-VOID-PAYMENTS A)
- No Invoice → Accrued linkage (Accrued = TimeEntry snapshot only)
- No Payment → Expected linkage (Expected = live Contract capacity only)

### 1.2 Application Services

- `getAccruedRevenue` / `calculateAccruedRevenue`

**AI Orchestrator** (`askWorkspaceQuestion`):

## 2. EXISTING INVOICE/PAYMENT WORKFLOW

### 2.1 Creation Paths (Contract-scoped)

**Invoice:**
1. Navigate to `/contracts/[contractId]`
2. Invoices section → "New Invoice" button
3. Form: `invoiceDate`, `amount`, optional `reference`
4. Currency/payment terms from Contract (read-only)
5. Server Action: `createInvoice`
6. Snapshot: Contract currency + paymentTermsDays
7. Compute: `dueDate = invoiceDate + paymentTermsDays` (null terms → null dueDate)
8. Redirect to Invoice detail

**Payment:**
1. Navigate to `/contracts/[contractId]/invoices/[invoiceId]`
2. Payments section → "New Payment" button
3. Form: `paymentDate`, `amount`, optional `notes`
4. Currency from Invoice (read-only)
5. Server Action: `createPayment`
6. Verify: Payment currency = Invoice currency
7. Redirect to Invoice detail

### 2.2 Discovery Gaps

**What PO cannot easily do today:**
1. "Show me all invoices across all contracts" → must visit each Contract detail
2. "Which invoices are overdue?" → Alerts exist, but no dedicated invoice list/filter
3. "What's my total invoiced vs. paid?" → no workspace summary (Accrued/Expected exist, but not Invoiced/Paid rollup)
4. "Export invoices to Excel" → not implemented
5. "Search invoices by reference or date range" → no search

**What PO CAN do today:**
- Create Invoice on any Contract (expired/archived-client OK)
- Record Payment on any ACTIVE Invoice
- See Invoice amount status (UNPAID/PARTIAL/PAID/MISMATCH)
- See overdue on Invoice detail
- Receive PAYMENT_OVERDUE alerts
- Edit/VOID Invoice (ACTIVE only)

### 2.3 Why Workflows Don't Need Redesign

- Forms are clear (date + amount + optional text)
- Currency/terms are read-only (correct enforcement)
- Validation is correct (amount > 0, currency = Contract)
- VOID is one-way and understood
- Payment events sum correctly
- Overdue alerts fire

**Problem is discoverability, not creation UX.**

- Reports remain a reporting/export surface
- Reports may link to Assistant, but Assistant is not embedded

**Boundaries:**
- Read-only tools (no Invoice/Payment writes)

- Membership guard (requireAiMembership)

- Application-generated citations (not authoritative prose)

- Anthropic Messages API
- Model: `claude-haiku-4-5-20251001`

**R2.2 must preserve:**

```typescript
listInvoicesForWorkspace(
```

- Every query scoped by `workspaceId`

- No cross-workspace leakage

### 7.2 Revenue Reporting Service Extension

**Extend ReportingService or create RevenueReportingService:**

```typescript
getRevenueOverview(
  context: WorkspaceContext,
  period: AnalyticsPeriod
): Promise<RevenueOverview>;

type RevenueOverview = {
  period: AnalyticsPeriod;
  accrued: AccruedRevenue;        // E01
  expected: ExpectedRevenue;       // E01
  forecast: ForecastRevenue | null; // E04 (if implemented)
  invoiced: InvoicedAmount[];      // NEW
  paid: PaidAmount[];              // NEW
  outstanding: OutstandingAmount[]; // NEW
};

type InvoicedAmount = {
  currency: string;
  amount: string; // sum of Invoice.amount where ACTIVE
};

type PaidAmount = {
  currency: string;
  amount: string; // sum of paidAmount where ACTIVE
};

type OutstandingAmount = {
  currency: string;
  amount: string; // invoiced - paid per currency
};
```

**Source:**
- Invoiced: `SUM(Invoice.amount) WHERE trackingState = ACTIVE AND invoiceDate IN period GROUP BY currency`
- Paid: `SUM(Payment.amount) WHERE Invoice.trackingState = ACTIVE AND Payment.invoiceId IN ... GROUP BY Invoice.currency`
- Outstanding: computed from invoiced - paid per currency

**Period membership:**
- Invoice: `invoiceDate` in period (same as TimeEntry workDate)
- Payment: follow Invoice period (Payment.paymentDate is NOT a period filter for Invoice-level aggregates)

**No profitability:**
- Do NOT compute `profit = Accrued - invoiced` or `margin = Accrued - costs`
- Costs are out of FreelanceOS domain

### 7.6 PDF Export Architecture

**Route:** `/reports/export/pdf` or `/invoices/export/pdf`

**Source:** Same as Excel

**Library options:**

**Option 1: `pdfmake` (recommended)**
- Declarative JSON-based
- Lighter than Puppeteer
- Good for table layouts
- No headless browser

**Option 2: `react-pdf`**
- JSX-based
- Reuse React components
- SSR-friendly

**Option 3: `puppeteer`**
- Render HTML → PDF via headless Chrome
- Heaviest (Chromium bundle)
- Good for complex layouts
- Slower

**Recommendation: `pdfmake` for R2.2**
- Simpler for table-based reports
- Faster than Puppeteer
- Good enough for professional layout

**Example:**
```typescript
import pdfMake from 'pdfmake/build/pdfmake';
import pdfFonts from 'pdfmake/build/vfs_fonts';

pdfMake.vfs = pdfFonts.pdfMake.vfs;

const docDefinition = {
  content: [
    { text: 'Revenue Report', style: 'header' },
    { text: `Period: ${startDate} - ${endDate}`, style: 'subheader' },
    {
      table: {
        headerRows: 1,
        widths: ['*', 'auto', 'auto'],
        body: [
          ['Metric', 'Currency', 'Amount'],
          ['Accrued', 'EUR', '5,000'],
          ['Expected', 'EUR', '6,000'],
        ],
      },
    },
  ],
  styles: {
    header: { fontSize: 18, bold: true, margin: [0, 0, 0, 10] },
    subheader: { fontSize: 12, margin: [0, 0, 0, 10] },
  },
};

const pdfDoc = pdfMake.createPdf(docDefinition);
pdfDoc.getBuffer((buffer) => {
  return new Response(buffer, {
    headers: {
      'Content-Type': 'application/pdf',
      'Content-Disposition': `attachment; filename="reports-${kind}-${start}-${end}.pdf"`,
    },
  });
});
```

**Layout:**
- Page 1: Revenue summary
- Page 2: HoursByClient
- Page 3+: ContractReport (auto page breaks)
- Optional: Invoice list

## 13. WORKSPACE ISOLATION CONSIDERATIONS

### 13.1 Invoice/Payment Queries

**All queries include `workspaceId`:**
```sql
SELECT * FROM Invoice WHERE workspaceId = ? AND ...
SELECT * FROM Payment WHERE invoiceId IN (SELECT id FROM Invoice WHERE workspaceId = ?)
```

**Composite FK isolation:**
- Invoice → Contract: `Invoice_workspaceId_contractId_fkey`
- Payment → Invoice: `Payment_workspaceId_invoiceId_fkey`

### 13.2 Filter Validation

**Filter.clientId / contractId:**
```typescript
if (filter.clientId) {
  const client = await clients.getClient(context.workspaceId, filter.clientId);
  if (!client) throw new InvalidFilterError();
}
```

**No resource id = tenant grant:**
- `invoiceId` alone does not authorize workspace access
- Every route resolves `WorkspaceContext` first

### 13.3 AI Workspace Isolation

- `requireAiMembership(context, members)`
- Every tool call passes `context.workspaceId`
- No tool accepts workspace id from user text
