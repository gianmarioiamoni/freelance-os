## 1. CURRENT ARCHITECTURE

### 1.1 Domain Model — FACT

**Entities:**
- `TimeEntry` → `Contract` → `Client`
- `TimeEntry` stores snapshot: `snapshotBillingModel`, `snapshotRate`, `snapshotCurrency`, `billable`, `durationMinutes`, `workDate`, `description`
- `Contract` defines: `billingModel` (HOURLY | DAILY), `rate`, `currency`, `validFrom`, `validTo`, `monthlyContractedMinutes`

**Billing Models (R2-OD-001, R2-OD-016):**
- **HOURLY**: `accruedAmount = billableMinutes / 60 × snapshotRate`
- **DAILY**: at most one billable day per Contract+workDate; weighted by minute distribution if multiple entries/rates same day

**Accrued Revenue Calculation — FACT:**
- Source: `calculateAccruedRevenue` in `src/application/analytics/accrued-revenue.ts`
- Input: `TimeEntry[]` with snapshot fields
- HOURLY: additive per entry
- DAILY: groups by `contractId` + `workDate` (calendar date), computes minute-weighted average rate
- Output: per-currency totals; per-contract totals; no FX; no mixed-currency sum

### 1.2 Existing Reporting Services — FACT

**AnalyticsService** (`src/application/analytics/analytics-service.ts`):
- `getAccruedRevenue(context, period, filter?)` → `AccruedRevenue`
- `getDailyAnalytics(context, period)` → `DailyAnalytics[]` (workDate, totalMinutes, billableMinutes, nonBillableMinutes, clientBreakdown)
- `getClientAllocations(context, period, filter?)` → `ClientAllocation[]` (client-level hour totals)
- Input: `AnalyticsRepository.listTimeEntriesForPeriod(workspaceId, period)` returns `AccruedTimeEntryFact[]`

**ReportingService** (`src/application/reporting/reporting-service.ts`):
- Thin orchestrator: resolves period from `Workspace.timezone`
- `getContractReport`, `getHoursByClient`, `getRevenueOverview` call `AnalyticsService`
- No billing calculation here; delegates to `AnalyticsService`

**Current Reports Page** (`/reports`):
- Sections: Revenue (Accrued/Expected/Forecast), HoursByClient, ContractReport, AnnualOverview
- Period selector: today/week/month/year/custom
- Entity filters: clientId, contractId
- Exports: CSV (meta + revenue + hours_by_client + contract_report), Excel (3 sheets: Revenue, HoursByClient, ContractReport), PDF (same datasets)

### 1.3 Current Data Flow — FACT

```
TimeEntry (with snapshot fields)
  → AnalyticsRepository.listTimeEntriesForPeriod
  → calculateAccruedRevenue (billing logic here)
  → AccruedRevenue DTO
  → ReportingService orchestration
  → Reports page UI
  → CSV/Excel/PDF serializers
```

**Key observation:** All billing calculation is centralized in `calculateAccruedRevenue`. No duplicate logic exists in reporting/export layers.

### 1.4 Existing Tests — FACT

**Coverage:**
- `tests/integration/analytics/accrued-revenue.test.ts`: HOURLY multi-entry, DAILY weighted, multi-currency, mixed contracts
- `tests/unit/application/analytics/accrued-revenue.test.ts`: edge cases (zero billable, mixed billing models, single-day DAILY)
- `tests/integration/analytics/expected-revenue.test.ts`: confirms DAILY Expected = null (capacity not defined for DAILY)
- No test explicitly validates "multiple contracts same client same month" scenario for timesheet report

## 4. PROPOSED REPORT STRUCTURE

### 4.1 Report DTOs — PROPOSAL

**MonthlyTimesheetReport:**
```typescript
type MonthlyTimesheetReport = {
  period: AnalyticsPeriod;
  periodKind: ReportingPeriodKind;
  filter: AnalyticsFilter; // clientId required
  clientName: string;
  totalMinutes: number;
  billableMinutes: number;
  accrued: AccruedRevenue; // filtered by clientId
  dailyBreakdown: TimesheetDayDetail[];
};
```

**TimesheetDayDetail:**
```typescript
type TimesheetDayDetail = {
  workDate: Date;
  totalMinutes: number;
  billableMinutes: number;
  entries: TimesheetEntryDetail[];
};
```

**TimesheetEntryDetail:**
```typescript
type TimesheetEntryDetail = {
  id: string;
  contractId: string;
  durationMinutes: number;
  description: string | null;
  billable: boolean;
};
```

### 4.2 Service Method — PROPOSAL

**ReportingService.getMonthlyTimesheet(context, request, clientId, now?):**
1. Require `clientId` in filter (fail closed if missing)
2. Call `AnalyticsService.getDailyAnalytics(context, period, { clientId })`
3. Call `AnalyticsService.getAccruedRevenue(context, period, { clientId })`
4. Call `TimeEntryRepository.listTimeEntriesForPeriod(workspaceId, period.startDate, period.endDate)` + filter by clientId
5. Group entries by workDate
6. Compute totalMinutes, billableMinutes from daily aggregates
7. Fetch client name from ClientRepository
8. Return `MonthlyTimesheetReport`

### 4.3 UI Structure — PROPOSAL

**New `/reports/timesheet` or transform `/reports`:**
- Month selector (default: current month)
- **Client selector (required)**
- Summary cards:
  - Total hours worked (format: Xh Ym)
  - Total billable hours (format: Xh Ym)
  - Amount to invoice (per currency, from `accrued.byCurrency`)
- Daily detail table:
  - Columns: Date, Hours, Billable Hours, Description (entry-level detail, truncated/expandable)
  - Footer: Monthly total
- Export buttons: CSV, Excel, PDF

## 5. MULTIPLE-CONTRACT BEHAVIOR

### 5.1 Same Client, Multiple Contracts — FACT + PROPOSAL

**Scenario:**
- Client A has Contract 1 (HOURLY, 80 EUR/h) and Contract 2 (HOURLY, 100 EUR/h)
- Month: June 2026
- TimeEntries reference both contracts

**Existing `calculateAccruedRevenue` behavior — FACT:**
- Groups by contractId internally
- Produces `AccruedRevenue.byContract[]` with separate row per contractId
- Produces `AccruedRevenue.byCurrency[]` aggregated across all contracts

**Proposed timesheet behavior — PROPOSAL:**
- Filter: `{ clientId: "A" }` captures all contracts for that client
- `accrued.byCurrency` returns summed revenue across Contract 1 + Contract 2
- Daily detail shows all entries regardless of contract
- "Amount to Invoice" = sum of `accrued.byCurrency` for that client

**Edge case: different currencies:**
- If Contract 1 = EUR, Contract 2 = USD → `accrued.byCurrency = [{ currency: "EUR", ... }, { currency: "USD", ... }]`
- Display both; no mixed total (consistent with existing R2.2 constraint)

### 5.2 Hourly vs Daily Billing — FACT

**Existing logic handles mixed billing models:**
- `calculateAccruedRevenue` processes HOURLY and DAILY separately
- Client filter applied to `TimeEntry.clientId` → captures all entries regardless of billing model
- Output: aggregated per currency

**Proposed timesheet:**
- Transparent to billing model at display level
- "Amount to Invoice" already correct per existing logic

### 5.3 Contract Validity Boundaries — FACT

**Existing behavior:**
- `calculateAccruedRevenue` uses `TimeEntry` snapshot fields only
- Contract validity not checked during accrued calculation (entries outside validity still counted)
- `ContractUtilization.isOutOfValidity` flag exists for contract report, not revenue

**Proposed timesheet:**
- No change; accrued revenue includes all billable entries in period
- If PO requires validity filtering, OPEN QUESTION

## 9. OPEN QUESTIONS

### 9.1 Navigation & IA — OPEN QUESTION

**Option A:** Transform `/reports` into timesheet-focused view
- Revenue/Contract/Annual sections move to `/dashboard` or removed
- Pros: simpler IA
- Cons: breaks existing E2E tests, removes useful analytics

**Option B:** Create new `/reports/timesheet` route
- Keep existing `/reports` unchanged
- Pros: backward compatible
- Cons: two report surfaces

**Option C:** Keep `/reports` but add "View: Analytics | Timesheet" toggle
- Pros: unified surface
- Cons: complex UI state

**Recommendation:** PO decision required.

### 9.2 Contract Validity Filtering — OPEN QUESTION

**Current behavior:**
- Accrued revenue includes entries outside contract validity (flagged in ContractUtilization)

**Question:**
- Should timesheet "Amount to Invoice" exclude out-of-validity entries?
- Or display all entries (current behavior) with a warning?

**Recommendation:** Default to current behavior (no change); add warning UI if `isOutOfValidity` detected.

### 9.3 Entry Detail Granularity — OPEN QUESTION

**Daily breakdown can include:**
- Just aggregates (totalMinutes, billableMinutes)
- Entry-level detail (description, contract, duration)

**Question:**
- Display all entry details inline, or expand/collapse per day?
- PDF: include entry detail or summary only?

**Recommendation:** Summary by default; expandable detail in UI; PDF summary only (keep concise).

### 9.4 Multiple Currencies in Single Client — OPEN QUESTION

**Scenario:**
- Client has Contract 1 (EUR) and Contract 2 (USD)
- Timesheet shows both currencies

**Question:**
- Display as two separate rows?
- Or single "Amount to Invoice" section with sub-rows?

**Recommendation:** Match existing Revenue section pattern (multiple rows, no total).
