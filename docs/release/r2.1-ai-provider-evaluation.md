## 2. Certified architecture constraints

The model is not financial truth.

Allowed: interpret the question; select one allow-listed read tool; refuse; clarify.

Forbidden: invent figures; decide validity / overdue / allocation / payment status; choose `workspaceId`; SQL; writes; manufacture citations.

Request to a provider (first hop only):

- application-owned system instructions
- current user question
- allow-listed tool names, descriptions, and argument keys

Not sent: `workspaceId`, `userId`, `role`, session, secrets, Prisma rows, financial DTOs. There is no second provider explanation round. Citations are assembled from tool DTOs after execution.

## 4. Evaluation methodology

1. Official documentation for capability, pricing, retention, EU/privacy, and hosting.
2. Isolated harness reuses `ANALYTICS_EVAL_CASES` unchanged.
3. Boundary cases (`SEC-*`) use adversarial Mock scripts. They measure the **application** when the model misbehaves.
4. Eval-only OpenAI-compatible HTTP adapter (`createEvalHttpAiProviderAdapter`) maps `tool_calls` / HTTP error / abort onto the certified port. It is not imported by the production resolver.
5. MODEL DECISION and APPLICATION TRUTH are recorded separately. Provider prose is never scored as a figure.

Canonical cases were not rewritten to improve a candidate.

## 11. Privacy / data handling

### Payload that would leave the app

If a live adapter is later authorized, the provider would receive only:

- system string
- user question text
- tool descriptors (`name`, `description`, `argumentKeys`)

It would not receive workspace identity, role, session cookies, API secrets, raw rows, VAT, notes, or computed money DTOs.

The eval HTTP adapter test asserts the outbound JSON omits `workspaceId`, `userId`, `OWNER`, and `correlationId`.

### Official retention / training (not assumed)

**OpenAI API** (https://developers.openai.com/api/docs/guides/your-data): API data is not used for training unless the customer opts in (stated as of 2023-03-01). `/v1/chat/completions` default abuse-monitoring retention is 30 days. Zero Data Retention is available after OpenAI approval. EU data residency is documented for listed models/endpoints; confirm the chosen snapshot on that page before any production use.

**Anthropic API** (https://platform.claude.com/docs/en/manage-claude/api-and-data-retention): ZDR is an organization-level arrangement requested via sales. Standard Messages prompts/outputs are not retained by default except Covered Models (Haiku 4.5 is not listed as a Covered Model). Client tool use on `/v1/messages` is the relevant path; do not enable server tools (web search, code execution) for R2.1.

**Ollama / self-host:** question text stays on the operator’s machine/VPC if no outbound proxy is added. Operational privacy then equals host hygiene. Not GDPR-automatic; still a processor if a third party hosts the GPU.

EU/privacy for sending minimized question + tool names is lower risk than sending DTOs, but the question can still contain client names typed by the user.

## 13. Managed API assessment

### Option A1 — OpenAI GPT-4o mini (`gpt-4o-mini-2024-07-18`)

Strengths:

- Native function calling and structured outputs (official).
- 128k context; 16,384 max output.
- Lowest published per-token price of the two API candidates.
- Same HTTP shape as the isolated eval adapter.
- Dated snapshot available.
- Chat Completions is ZDR-eligible after approval.

Weaknesses:

- Default 30-day abuse-monitoring logs unless ZDR is approved.
- EU residency must be confirmed for the exact snapshot and org setting; not automatic.
- Live tool-selection quality on Italian GP/RF text is NOT MEASURED.

Operational implications: one `fetch` adapter; one Vercel secret; no GPU. Production must stay Null until a PO enablement decision.

Unresolved: live GP/RF accuracy; ZDR approval; EU endpoint for this org; monthly volume.

### Option A2 — Anthropic Claude Haiku 4.5 (`claude-haiku-4-5-20251001`)

Strengths:

- Native client tool use (official).
- 200k context; 64k max output.
- Fastest model in Anthropic’s current comparison table.
- Dated snapshot. ZDR available on request for non-Covered models.
- Client tools are token-priced only (do not attach Anthropic server tools).

Weaknesses:

- Higher published unit price than GPT-4o mini.
- Requires a Messages-API mapper; not drop-in OpenAI JSON.
- Live GP/RF quality is NOT MEASURED.

Operational implications: still one adapter port; slightly more mapping code; one secret; Vercel-compatible.

Unresolved: live GP/RF accuracy; ZDR contract; whether Haiku tool use on Italian analytics questions is reliable enough for §8.5.

## 14. Open-source / self-hosted assessment

### Option B1 — Llama 3.1 8B Instruct via Ollama (OpenAI-compat)

Strengths:

- Official Ollama OpenAI-compat tools support; Llama 3.1 is listed on the tools announcement.
- Question text can remain on operator infrastructure.
- No per-token vendor bill.
- Same eval HTTP adapter if the host exposes `/v1/chat/completions`.

Weaknesses:

- Not runnable as Vercel Serverless GPU. Needs a separate inference host.
- Cold start and CPU latency can miss the 5s p95 target. NOT MEASURED.
- `tool_choice` unsupported on Ollama’s documented OpenAI-compat surface.
- Community reports of malformed/nested tool arguments on some Qwen tags; Llama 3.1 is the evaluated OSS class, not Qwen.
- No dated vendor snapshot unless the operator pins a digest.
- Tool-calling quality is NOT MEASURED.

Operational implications: new runtime, updates, GPU/CPU capacity, backups, and a network path from Vercel to the host. That must not block R2 deploys. Do not embed inference in the Next.js app.

Cost at small/medium usage: electricity + instance. Monthly USD is **NOT MEASURED**.

B1 is also not §8.5-eligible without a live score sheet.
