## R21-OD-CR-01 — Overview / hours

**Decision ID:** R21-OD-CR-01  
**Status:** CLOSED  
**Selected option:** B

**Intent**

- Eliminate sibling-overview ambiguity.
- Preserve both tools.
- No new routing layer.

- Do not add a hours-total tool (D).
- Do not add a pre-model router.

## R21-OD-CR-04 — Refusal channel

**Decision ID:** R21-OD-CR-04  
**Status:** CLOSED  
**Selected option:** B

Introduce native sentinel `refuse` through tool calling.

**Intent**

- `unsupported_capability` → refuse
- `write_forbidden` → refuse
- `injection` → refuse
- prose refusal → error
- prose must NEVER become success
- no refusal facts
- refusal cannot execute application reads/writes
- application remains authoritative for final outcome normalization

**Consequences**

When later authorized, unsupported / write / injection must be expressed via a native allow-listed refuse tool. Orchestrator maps that call to `outcome: "refusal"` with empty facts/citations. Unstructured prose stays `error`. Application safety and grounding stay application-owned.

**Explicit non-goals**

- Do not keep text-only `AiRefusalClass` as the sole expression channel (A).
- Do not implement the refuse tool in this record.
- Do not change adapters, `tool_choice`, structured output, or RF-01…RF-06 expected classes in this record.
- Do not let a refuse path execute services, Prisma, SQL, or writes.
- Do not promote prose to `success`.
