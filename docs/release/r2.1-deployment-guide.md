## Deployment Steps

### 1. Configure Production Environment

Add environment variables via your hosting platform (Vercel/other):

```bash
AI_PRODUCTION_ENABLED=true
AI_PRODUCTION_BASE_URL=https://api.anthropic.com/v1
AI_PRODUCTION_API_KEY=<your-anthropic-api-key>
AI_PRODUCTION_MODEL=claude-haiku-4-5-20251001
```

**Security checklist:**
- [ ] Variables are server-only (no `NEXT_PUBLIC_` prefix)
- [ ] API key stored in secure secrets manager
- [ ] API key never committed to repository
- [ ] All 4 variables configured (partial config → Null fallback)

### 2. Deploy

```bash
git checkout 90662e5
# Deploy via your platform (e.g., Vercel, Railway, AWS)
```

### 3. Verify Deployment

Check that the production build includes AI configuration:

- Dashboard has "Ask about your analytics" box
- Reports has "Ask about your analytics" box
- No build errors
- No environment variable warnings

### 4. Execute Smoke Test (Optional)

If you have CLI access to the production environment:

```bash
npx tsx scripts/smoke-test-production-ai.ts
```

Expected output:
```
✓ PASS: Provider Resolution
✓ PASS: Provider Availability
✓ PASS: Tool Call Structure
✓ PASS: Timeout Enforcement

SMOKE VALIDATION PASSED
```

### 5. Live Validation

Execute one test question via the production UI:

**Dashboard or Reports → AI ask-box:**

```
Quanto ho maturato a gennaio 2026?
```

**Expected outcome:**
- Response contains Italian prose with revenue figure
- Response includes citations (e.g., "Contract X: €Y")
- No error message
- No "AI unavailable" message

**If error occurs:**
- Check production logs (no stack traces should be visible to user)
- Verify API key is valid
- Verify all 4 environment variables are set
- Check Anthropic API status

### 6. Monitor Initial Usage

**First 24 hours:**
- AI request volume
- Success rate (should be >90% for valid questions)
- Refusal rate (expected for out-of-scope questions)
- Error rate (should be <5%)
- p50/p95 latency (expected: ~1100ms / ~2000ms)
- Cost per request (expected: ~$0.005)

**Alert conditions:**
- Error rate >10%
- p95 latency >8000ms (timeout)
- Credential leakage in logs
- Cross-workspace data in responses

## Rollback Procedure

If blocking issues are detected:

### Immediate Rollback

```bash
# Via hosting platform dashboard or CLI:
AI_PRODUCTION_ENABLED=false
```

Or unset all AI variables.

**Effect:**
- AI ask-box remains visible
- All AI requests return "AI unavailable" message
- No provider calls
- No API costs
- No code changes required

### Verify Rollback

1. Submit AI question via Dashboard/Reports
2. Expected: "AI unavailable" message
3. No errors, no crashes

## Troubleshooting

### "AI unavailable" in production

**Cause:** Missing or invalid credentials

**Fix:**
1. Verify `AI_PRODUCTION_ENABLED=true`
2. Verify all 4 variables are set
3. Verify API key is valid
4. Check production logs for configuration errors

### HTTP 401/403 errors

**Cause:** Invalid Anthropic API key

**Fix:**
1. Verify API key in Anthropic dashboard
2. Regenerate key if necessary
3. Update `AI_PRODUCTION_API_KEY` in production environment
4. Redeploy

### Timeout errors

**Cause:** Network latency or Anthropic API slowness

**Fix:**
1. Check Anthropic API status
2. Monitor p95 latency
3. If persistent, consider increasing timeout (currently 8000ms)

### Unexpected responses

**Cause:** Provider behavior outside certified contract

**Fix:**
1. Check production logs for request/response details
2. Document case in residual analysis
3. Verify no safety regression (no writes, no invented data)
4. If safety regression: rollback immediately
5. If quality issue only: document and monitor
