# Database Data Reset Utility

**Version:** R2.1  
**Status:** IMPLEMENTED  
**Purpose:** Safe data-only reset for local AND remote/production databases

---

## Overview

Universal utility to delete all application data while preserving database structure.

Works on:
- ✓ Local development databases
- ✓ Remote databases (Vercel, Supabase, Railway, Neon, etc.)
- ✓ Production databases (with explicit flags and multiple confirmations)

This is a **DATA-ONLY RESET** — schema, migrations, and structure remain intact.

---

## Key Difference from Vercel "Reset Database"

| Operation | Vercel Reset | This Script |
|-----------|--------------|-------------|
| Schema | ✗ Deleted | ✓ Preserved |
| Migrations | ✗ Deleted | ✓ Preserved |
| Data | ✗ Deleted | ✗ Deleted |
| Indexes | ✗ Deleted | ✓ Preserved |
| Enums | ✗ Deleted | ✓ Preserved |
| Requires rebuild | ✓ Yes (`db:migrate:deploy`) | ✗ No |

---

## What Is Deleted

All rows from:
- `Notification`, `Alert`, `Payment`, `Invoice`, `TimeEntry`
- `Contract`, `Client`, `WorkspaceSettings`, `WorkspaceMember`, `Workspace`
- Better Auth: `session`, `account`, `verification`, `user`

---

## What Is Preserved

- All tables, columns, constraints, indexes, enums
- All Prisma migrations and `_prisma_migrations` table
- Database schema structure
- PostgreSQL extensions

---

## Commands

### Local Database

#### Dry Run
```bash
pnpm db:reset-data -- --dry-run
```

#### Execute
```bash
pnpm db:reset-data -- --confirm
```

### Remote/Production Database

#### Dry Run
```bash
pnpm db:reset-data -- --dry-run --allow-remote
```

#### Execute (requires double confirmation)
```bash
pnpm db:reset-data -- --confirm --allow-remote
```

---

## Safety Mechanisms

### For Local Databases
- Requires `--confirm` flag
- 3-second countdown with Ctrl+C abort window
- Pre/post structure validation
- Transaction-based execution (atomic rollback on failure)

### For Remote/Production Databases
- Requires `--confirm` AND `--allow-remote` flags
- **Two separate 5-second confirmation windows**
- Explicit warnings about remote database
- Database identity display
- Backup reminder
- Stakeholder notification reminder

## Usage Examples

### Reset Local Development Database
```bash
# Check what will be deleted
pnpm db:reset-data -- --dry-run

# Execute reset
pnpm db:reset-data -- --confirm
```

### Reset Production Database on Vercel
```bash
# Set production DATABASE_URL (from Vercel environment variables)
export DATABASE_URL="postgresql://user:pass@db.vercel-postgres.com/prod"

# Dry run first
pnpm db:reset-data -- --dry-run --allow-remote

# Execute with double confirmation
pnpm db:reset-data -- --confirm --allow-remote
```

### Reset via Direct Connection
```bash
# Connect directly to remote database
DATABASE_URL="<your-prod-url>" pnpm db:reset-data -- --confirm --allow-remote
```

## Pre-Production Checklist

Before running on production:

- [ ] **Backup created**: `pg_dump` or provider snapshot
- [ ] **Stakeholders notified**: team, users, clients
- [ ] **Downtime scheduled**: maintenance window if applicable
- [ ] **DATABASE_URL verified**: double-check connection string
- [ ] **Dry run executed**: `--dry-run --allow-remote` to verify target
- [ ] **Recovery plan ready**: know how to restore from backup
- [ ] **Monitoring prepared**: be ready to verify application state post-reset

---

## Recovery

### From Backup
```bash
# PostgreSQL restore
psql -U <user> -d <database> < backup.sql

# Or use provider's restore interface
```

### No Backup Available
- Data is permanently lost
- Rebuild manually via application UI
- Users must re-register

## Comparison with Other Reset Methods

### `pnpm db:reset` (Prisma Migrate Reset)
- ✗ Drops and recreates entire database
- ✗ Deletes schema and migrations
- ✓ Rebuilds from migration files
- ✗ Runs seed if configured
- **Use case:** Development only, full schema rebuild

### `pnpm db:reset-local` (Local-Only Script)
- ✓ Data-only reset
- ✓ Preserves schema/migrations
- ✗ Blocked on remote databases
- **Use case:** Safe local development reset

### `pnpm db:reset-data` (This Script)
- ✓ Data-only reset
- ✓ Preserves schema/migrations
- ✓ Works on local AND remote
- ✓ Multiple safety confirmations for remote
- **Use case:** Production-ready data reset

### Vercel Dashboard "Reset Database"
- ✗ Deletes everything (schema + data)
- ✗ Requires `db:migrate:deploy` after
- **Use case:** Complete database rebuild

## Troubleshooting

### Error: "Table does not exist"
- Schema is incomplete or damaged
- Run `pnpm db:migrate:deploy` to rebuild schema
- Restore from backup if available

### Error: "Some tables still contain data"
- Foreign key constraints may have blocked deletion
- Transaction was rolled back
- Check PostgreSQL logs
- Verify schema constraints are as expected

### Script refuses to run on remote
- Add `--allow-remote` flag
- Verify `DATABASE_URL` is set correctly
- Check database connectivity
