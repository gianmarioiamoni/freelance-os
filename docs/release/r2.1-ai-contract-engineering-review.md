## CR-01 - Overview / hours (PO B)

**Required:** `get_current_month_analytics` owns implicit current-month hours. `get_monthly_analytics` must not advertise hours as its primary semantic. Omitted period / “questo mese” / `periodKind=month` must not be the catalog-valid route to the monthly sibling. No router. No service change.

| Surface | Evidence |
| --- | --- |
| Model-facing description | Current-month tool owns implicit current-month briefing and hours; binds omitted-period / questo mese. Monthly tool owns explicit-period briefing; leads with that ownership; MUST NOT for implicit hours / omitted period / questo mese; `periodKind=month` is not a substitute. |
| System text | “Implicit current-month hours use get_current_month_analytics, not get_monthly_analytics.” |
| Provider schema | Current-month: zero args. Monthly: period keys only. `periodKind=month` remains a legal named kind (no router). |
| Orchestrator | No new branch that rewrites monthly → current-month. |
| Tests | `tool-semantic-contract.test.ts` ownership bindings; GP-06 expected tool unchanged; harness asserts `get_current_month_analytics`. |
| Canonical expected tool | GP-06 stays `get_current_month_analytics`. |

**Residual (INFO / C):** if a live model still calls `get_monthly_analytics` `{periodKind:month}`, the application will execute it. That is the no-router consequence, not a silent ownership revert. Live sibling selection belongs to the provider-retest gate.

## CR-04 - Refusal path (PO B) - PRIORITY

Inspected path:

`provider tool call` → allow-list → `sanitizeToolArgs` → `mapRefuseToolCall` → class validation → orchestrator outcome → empty facts/citations → no service execution.

| Rule | Evidence | Result |
| --- | --- | --- |
| Accepted classes on `refuse` | Schema enum + `AI_SENTINEL_REFUSE_CLASSES` + `isSentinelRefuseClass`: only `unsupported_capability`, `write_forbidden`, `injection`. | Pass |
| Unknown class → error | `mapRefuseToolCall` → `kind: "error"`; orchestrator `outcome: "error"`; no `refusalClass`. Tested. | Pass |
| Malformed refusal → error | Extra JSON keys / unknown text class → adapter `malformed_refusal` or envelope `malformed` → `error`. Tested. | Pass |
| No service execution | Mapping occurs before `tool.execute`. `refuse.execute` throws `InvalidAiToolError`. Analytics stub context unset on refuse. | Pass |
| No facts / citations | `emptyAnswer()` on every refuse / error / adapter-refusal path. | Pass |
| No tenant identity from model | `argumentKeys: ["class"]` only. Registry rejects `workspaceId` / `userId` / `role`. Sanitize strips forbidden + unknown keys. Mapping reads only `class`. | Pass |
| Allow-listed | Analytics + foundation registries. Unknown names still `unsupported_capability`. | Pass |
| Cannot become a write | `readOnly: true` required by registry. No write tools. Execute throws. | Pass |
| `execute` cannot be a normal read | Orchestrator never reaches execute on `refuse`. Direct invoke throws. `mapToolFailure` maps unknown errors to generic `error`, not `success`. | Pass |
| Prose → error, never success | `message` → `error`. SEC-PROSE: L5 pass, L6 fail. | Pass |
| Adapter fallback fail-closed | First-class adapter `status: "refusal"` still accepted if class is an `AiRefusalClass`. Text envelope kept as fallback A. Prose / malformed stay `error`. | Pass |
| Refuse + another tool | `toolCalls.length !== 1` → `error`, empty facts, no execute (same one-tool rule as SEC-MULTI). | Pass |
| Membership | `requireAiMembership` is the first statement. Refuse cannot skip it. | Pass |
| User text cannot forge refusal | Question is adapter input only (`parseAiQuestion`). Envelope parsing applies to adapter output, not the user string. | Pass |

Scripted RF-01…RF-06 now emit `refuse` with the expected class. Frozen `scoreEvalCase` refusal check is unchanged (`outcome === "refusal"` + class).

Text-channel fallback still accepts the broader `AiRefusalClass` set (including application clarification classes) if an adapter emits that envelope. That is the planned keep-A fallback, not a new sentinel leak. The `refuse` tool itself rejects those classes.
