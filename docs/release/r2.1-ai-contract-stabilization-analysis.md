## GP-03 Analysis

Question (**FACT**): `Quanto ho maturato questo mese?`  
Expected (**FACT**): `get_accrued_revenue` `{periodKind:month}`.  
Observed (**FACT**): both providers `get_current_month_analytics` `{}` → grounded overview `success`.

### What changed

**FACT.**

| Surface | Hardened | Revised |
| --- | --- | --- |
| Overview | Advertises Accrued among combined metrics; negative exclusivity only | Drops metric advertising. Adds MUST-select for omitted-period / `questo mese` hours and briefing. Keeps “does not own a single Accrued/Expected/Forecast metric.” |
| `get_accrued_revenue` | Owns Accrued; “use only when specifically for Accrued”; English name only | Unchanged |
| System | Do not substitute overview for a specialized metric | Same line, plus MUST-select current-month hours onto the overview |
| Schema / name / order | Unchanged | Unchanged |

### Why the revised contract can attract the wrong tool

**FACT.** The user question contains `questo mese` and Italian `maturato`. It does not contain the English word `Accrued`.

**FACT.** The overview now says it **must** be selected for `questo mese` hours and briefing. The specialist still requires the question to ask “specifically for Accrued.”

**INFERENCE.** Those two sentences compete. A competent reading can treat `questo mese` as overview-owned and treat `maturato` as not “specifically Accrued.” That reading was not available under the hardened contract, where the overview’s only discriminator was “not a substitute for one specific metric” and both providers then chose Accrued.

**INFERENCE.** A1 missing only GP-03 (and still passing GP-04/GP-05, which name Expected/Forecast in English) is consistent with a language gap on Accrued **plus** the new `questo mese` MUST-select. A2 missing GP-03/04/05 together is consistent with an over-broad `questo mese` / briefing parse, not with Accrued-only wording.

**FACT.** The overview DTO still contains Accrued. Execution of the wrong tool is therefore grounded. That is routing, not invented money. ER-01 (monthly sibling still executable) was not observed.

### Is the expected tool still uniquely justified?

**FACT.** Canonical expected tool is unchanged (`analytics-eval-cases.ts`). Discovery originally allowed Accrued **or** the current-month DTO. Hardening proved both measured models can select the specialist under exclusivity text. PO did not reopen GP-03 ownership.

**INFERENCE.** Under the current eval pin and the hardened-contract control, `get_accrued_revenue` remains the unique owner of named Accrued / `maturato`. The overview remains the owner of briefing and implicit hours, not of a single revenue metric.

### Smallest possible correction

**RECOMMENDATION.** Do not rewrite the specialist. Disambiguate the overview MUST-select so it covers hours and briefing only, and add an explicit MUST NOT for named single revenue metrics (Italian `maturato` and English Accrued / Expected / Forecast) even when the question contains `questo mese`. Optionally bind `maturato` on `get_accrued_revenue` as a secondary, A1-GP-03-only aid — not as the shared fix.
