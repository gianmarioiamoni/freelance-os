# Local Database Reset Utility

**Version:** R2.1  
**Status:** IMPLEMENTED  
**Purpose:** Safe, offline-only utility to delete all application data while preserving database structure

---

## Overview

The local database reset utility empties the FreelanceOS PostgreSQL database of all application data without altering the database schema, migrations, or structure.

This is a **DATA RESET**, not a schema reset.

---

## What Is Deleted

All rows from these tables:

### Application Domain
- `Notification`
- `Alert`
- `Payment`
- `Invoice`
- `TimeEntry`
- `Contract`
- `Client`
- `WorkspaceSettings`
- `WorkspaceMember`
- `Workspace`

### Better Auth
- `session`
- `account`
- `verification`
- `user`

---

## What Is Preserved

- All tables
- All columns
- All constraints
- All indexes
- All enums
- All Prisma migrations
- `_prisma_migrations` table
- Database schema structure
- PostgreSQL extensions

---

## Safety Mechanisms

### Production Protection
The script refuses to run if:
- Hostname is not `localhost`, `127.0.0.1`, `::1`, or `0.0.0.0`
- Hostname contains production keywords: `prod`, `production`, `vercel`, `railway`, `heroku`, `aws.com`, `azure.com`, `supabase.co`

### Explicit Confirmation
The script requires:
- `--confirm` flag for destructive execution
- `--dry-run` flag for inspection
- Default behavior is refusal with usage instructions

### Additional Safety
- 3-second countdown before execution
- Ctrl+C abort window
- Database identity printed (hostname/database name only, no credentials)
- Transactional execution (all-or-nothing)
- Pre-reset structure validation
- Post-reset structure validation
- Post-reset row count verification

## Commands

### Dry Run (Inspection)
```bash
pnpm db:reset-local -- --dry-run
```

Reports:
- Target database identity
- Current row counts for all tables
- No destructive operation performed

### Destructive Execution
```bash
pnpm db:reset-local -- --confirm
```

Executes:
- Pre-reset structure validation
- Pre-reset row count report
- 3-second countdown
- Transactional data deletion
- Post-reset row count verification
- Post-reset structure validation

## Recovery

### No Built-In Undo
This operation is **IRREVERSIBLE** for the target database.

### Recovery Options
1. **PostgreSQL Backup Restore**
   - If you have a `pg_dump` backup, restore it:
     ```bash
     psql -U <user> -d <database> < backup.sql
     ```

2. **Prisma Seed**
   - Run seed data if available:
     ```bash
     pnpm db:seed
     ```
   - Note: Seed data is test data, not your real data

3. **Manual Re-Entry**
   - Start the application
   - Create a new user through the sign-up UI
   - Enter real data manually

### Prevent Data Loss
- Always maintain regular database backups
- Use `pg_dump` before destructive operations
- Consider point-in-time recovery if supported by your hosting provider

## Implementation Details

### Deletion Order
Foreign key dependencies are resolved in this order:
1. `Notification` → references `Alert`, `WorkspaceMember`
2. `Alert` → references `Client`, `Contract`, `Invoice`
3. `Payment` → references `Invoice`
4. `Invoice` → references `Contract`
5. `TimeEntry` → references `WorkspaceMember`, `Client`, `Contract`
6. `Contract` → references `Client`
7. `Client`
8. `WorkspaceSettings`
9. `WorkspaceMember`
10. `Workspace`
11. Better Auth tables: `session`, `account`, `verification`, `user`

### Transaction Atomicity
All deletions occur in a single PostgreSQL transaction:
- On success: all data deleted, transaction committed
- On failure: transaction rolled back, no partial deletion

### Prisma Usage
- Uses Prisma Client for type-safe deletion
- Uses `deleteMany` for application models
- Uses raw SQL `DELETE` for Better Auth tables (not in Prisma schema as relations)
- No schema modifications
- No migrations executed
- No `TRUNCATE ... CASCADE` blind operations

---

## Validation

### Pre-Reset
- Checks existence of all expected tables
- Reports current row counts

### Post-Reset
- Verifies all expected tables still exist
- Verifies row counts are zero
- Reports any unexpected non-zero counts

---

## Warning

**THIS OPERATION IS IRREVERSIBLE.**

- All application data will be permanently deleted
- Better Auth users and sessions will be deleted
- No application-level undo mechanism exists
- Recovery requires external database backup

**ALWAYS:**
- Run `--dry-run` first
- Maintain regular database backups
- Never run against production
- Verify the target database identity before confirming
